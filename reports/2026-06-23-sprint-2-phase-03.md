## Design Decisions

### Why `chunkSizeWarningLimit: 300` not 500
500 KB is the Vite default. Setting 300 is a tighter guardrail that flags potential bundle bloat earlier. Chart.js alone is ~200 KB, so 300 leaves 100 KB headroom for app code. Any future addition that pushes the bundle past 300 KB triggers a warning during build.

### Why rename IDs to `cancellationFlow` instead of leaving the `mermaid` name
The old IDs (`#cancellationMermaid`, `#mermaidInlineNote`) were semantically wrong after the mermaid library was removed. The new names match the actual function (`renderCancellationFlow`) and the class on the container (`cancellation-flow`). This is a no-risk rename because:
- The IDs are only referenced in `ui.js`, `main.js`, and the test file
- All 4 references were updated atomically in this commit
- Tests verify the new IDs work

### Why no view transitions / resize listener for chart radii
The chart is set up once at init. If a user resizes from desktop to mobile, the radii don't update. This is acceptable because:
- The user experience is "the chart looks reasonable on first load" — true
- The test viewport tests confirm the initial setup is correct
- Adding a `window.matchMedia` listener + chart re-init would add complexity for a rare edge case (user resizes browser during a workshop demo)
- The plan didn't require it (TASK-02-01 was: "In chart.js, increase the base (non-selected) pointRadius" — no resize requirement)
