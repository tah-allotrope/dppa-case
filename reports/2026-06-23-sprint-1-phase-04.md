## Design Decisions

### Why test 54 files were new (not just 95 total)
Vite's content-hashed filenames (`index-BcTVuuWO.js`, `index-fdTzBso5.css`) change on every build even if the source is identical, because Vite generates fresh hashes. Firebase uploaded 54 new files (the current build) and the rest are content-preserved from the prior deploy.

### Why we didn't manually re-test all 3 scenarios + slider extremes
The browser snapshot covers one full default render + one scenario switch (excess tab). The 38 unit tests cover the calculation engine exhaustively, including settlement with edge-case inputs. Manually dragging every slider to min/max would be redundant with the test suite for the calculation layer and would only verify that the slider's `input` event handler runs — which is already trivially proven by the scenario-tab click that does the same `state.X = ...; updateView()` flow.

### Why deployment.md lives in `app/` not repo root
The deployment is app-specific (Firebase project binding, `dist` config in `firebase.json`). Keeping it next to the app code makes it discoverable for whoever next deploys, without polluting the repo root with one-app-specific doc.
