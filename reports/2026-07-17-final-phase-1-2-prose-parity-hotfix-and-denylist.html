01 / Executive Summary

Executive Summary

What was found

A fresh verification pass on 2026-07-17 discovered that a July 11 fix — which upgraded the M5 gate-sweep headline from a placeholder "0 of 56" to a computed "5 of 56" — never fully propagated. Three living documents (a lender-panel answer key and two learner lesson pages) still stated the retired figure, meaning a presenter reading from the panel guide would have said "zero" in a room where the deck said "five."

What was done

Phase 1 corrected all five occurrences across the three files and reframed the surrounding narrative from an "empty window" to a "narrow window" story so the prose matches the number. Phase 2 built a permanent CI gate — a retired-figures denylist checker — so any future headline change that isn't fully propagated fails the build instead of surviving silently for six days.

Verification posture

Every claim in this report is grounded in commands actually run this session: the stale-reference grep, the new checker's pass/fail output, a planted-failure drill that proved the gate can fail, 8 passing unit tests, and confirmation that the pre-existing deck verifiers (audit_teaching_deck.py, verify_deck_numbers.py) were unaffected.

What's still open

The underlying plan has five phases; only the first two (repo hygiene + denylist) are executed. Phases 3–5 — generating S2/S3 spine exports from the settlement engine, rewiring the printed Word handout to read from them instead of hand-typed figures, and closing the FMP/decree sourcing gaps — remain not yet executed and are the natural next session's work.

02 / Background & Objective

Background & Objective

This repository teaches the Vietnam DPPA (Direct Power Purchase Agreement) settlement mechanics to factory CFOs and lenders via a slide deck, a live web app, printed handouts, and facilitator guides — all of which must agree on the same numbers. An earlier hardening effort made the deck pipeline trustworthy: the settlement engine (app/src/modules/settlement.js) computes every figure, exports it to JSON, and a CI job (deck-parity) regenerates and diffs those exports on every push.

A 2026-07-17 review found that trustworthiness stops at the deck. The prose artifacts — facilitator guides, lesson HTML pages, and the Word document participants take home — carry the same canonical figures hand-typed, with no equivalent check. The proof this gap is real, not theoretical: three documents were still stating a retired placeholder figure ("0 of 56" gate-sweep pass count) six days after the correct value ("5 of 56") was computed and shipped everywhere else.

The objective of the governing plan (plans/2026-07-17-prose-parity-second-pipeline-plan.md) is to close this second pipeline: fix what's wrong today, build a permanent gate against recurrence, extend the engine's JSON exports to the two scenarios (S2, S3) it doesn't yet cover, wire the handout generator to read from them, and add a verifier that any large figure in prose is either an engine export or an explicitly justified literal. This report covers the first two of that plan's five phases.

04 / Assumptions & Constraints

Assumptions & Constraints

Assumptions applied

  • ASM-001 — the "0 of 56" references were judged stale, not intentional historical framing (no document frames "0" as a July-era figure; the panel guide predates the real sweep). Applied: update to the current computed value with narrow-window framing.
  • ASM-003 — "living" documents (subject to the checker) are NOTES.md, RESOURCES.md, MISSION.md, lessons.md, facilitator/**/*.md, lessons/**/*.html. Historical records (plans/, research/, reports/, learning-records/) are permanently exempt.
  • ASM-006 — retired-figure matching is case-insensitive substring, line-by-line, plain strings only (no regex) — kept the config auditable at the cost of some intentional over-matching (see Risks).

Constraints honored

  • CON-002 — no requirements.txt exists yet in this repo (that's the companion plan's job), so every new Python file this session uses the standard library only: json, pathlib, sys, unittest, tempfile.
  • CON-003 — no number, formula, or engine call was modified.
  • Windows-authoring constraint: local commands were run with the documented PYTHONPATH= prefix (a stale PYTHONPATH on the author's machine otherwise shadows imports); this is harmless elsewhere and preserved in every documented command.
05 / Methodology

Methodology

Each phase followed the same discipline: implement the exact tasks specified in the plan, run the closest available verification (a targeted grep sweep for Phase 1; the new checker plus its unit tests and a planted-failure drill for Phase 2), fix anything red before committing, then commit with a message that traces back to the plan's task IDs. Nothing was marked done without a command actually producing the expected output in this session.

Phase 2's checker was specifically validated with a planted-failure drill: the retired string was temporarily reintroduced into NOTES.md, the checker was run and confirmed to exit 1 naming the exact file and line, and only then was the change reverted (confirmed via git diff --stat showing no residue). This follows the plan's own principle: "a gate never seen failing is not known to work."

A repo-hygiene side effect was also caught and corrected mid-session: the new Python module's compiled bytecode (__pycache__/*.pyc) was auto-staged by git add -A; this was unstaged, deleted, and __pycache__/ / *.pyc were added to .gitignore before the Phase 2 commit, so no build artifact entered history.

Committed the four previously-untracked planning documents as one commit (preserving planning state independent of execution), confirmed and deleted the empty cc-nightly/20260710-213046 branch (zero unique commits vs master, verified before deletion) both locally and on origin, then fixed five occurrences of the retired figure across three files:

PHASE-02 — Retired-Figures Denylist Done

Built tools/check_retired_figures.py (stdlib-only) plus its config tools/retired_figures.json, which scans six living-document globs for five denylisted phrasings of the retired figure. Added 8 unit tests in tools/tests/test_check_retired_figures.py covering case-insensitivity, an intentional substring-strictness edge case, an empty-denylist no-op, and a missing-config failure. Wired two new steps into the existing deck-parity CI job. Proved the gate works with a planted-failure drill, then reverted the plant cleanly.

This phase is the direct answer to what Phase 1 revealed: the same class of drift (a headline changes, not every reference updates) will recur the next time the gate-sweep number moves — which the companion plan's own PHASE-01 is expected to trigger. The denylist's config file carries an explicit note telling that plan's executor which new strings to add when that happens.

07 / Findings & Recommendation

Findings & Recommendation

Finding 1 — the drift was real and audience-facing. The worst instance was in facilitator/dppa-panel-guide.md, a document written specifically to prep answers for a live lender panel. A presenter using it would have confidently stated a number the deck itself no longer supported. This was not a cosmetic typo; it was a live factual inconsistency between two artifacts the same audience could see side by side.

Finding 2 — a one-time fix wasn't the actual gap; the missing mechanism was. The July 11 sprint's own completion report claimed the facilitator references were updated. It updated one of at least four locations. The lesson isn't "look harder next time" — it's that any manual propagation step across N files will eventually miss one, and only a mechanical check catches that reliably. Phase 2's denylist is that mechanism.

Finding 3 — the fix generalizes cheaply. The checker's config-driven design means the companion gate-credibility plan (expected to retire "5 of 56" itself when it extends the sweep grid) has a documented, one-line-per-phrase extension point already in place, rather than needing to invent its own propagation-safety mechanism.

Recommendation: proceed to PHASE-03 (S2/S3 spine exports) next. It has no dependency on the still-open FMP/decree research (PHASE-05, parallelizable) and directly enables PHASE-04's handout rewire, which retires the single largest remaining source of hand-typed canonical figures in the repository — the printed document participants take home and cannot be hot-fixed once distributed.

09 / Risks / Open Questions

Risks / Open Questions

Known risks

  • The "5 of 56" value just written will itself retire soon. The companion plan's gate-sweep rework is expected to move the headline to a band out of a larger grid (~70 cells). This is by design — Phase 2's denylist is exactly the mechanism that will flag any straggler when that happens, per the coordination note above.
  • Substring matching is intentionally strict. A phrase like "10 of 56" would trip the checker because it contains "0 of 56." This is documented and tested as deliberate: any future headline phrasing should use the computed figure rather than a hand-typed number that happens to share a suffix.

Open questions (deferred to later phases)

  • Whether the lender/investor gate proxy constants (currently illustrative) will be recalibrated with real Allotrope deal data — explicitly out of scope for both this plan and the companion plan; needs private data a human must supply.
  • The October session date remains unconfirmed as of this report; PHASE-05's human-blocked register (not yet built) will need updated dates once it is.
