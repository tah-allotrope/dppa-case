03 / Math / Algorithm Used

Math / Algorithm Used

Number extraction regex: \d{1,3}(?:,\d{3})+ — matches only comma-thousands-grouped figures (4+ digits), which is exactly the format every on-slide VND-millions figure uses in this deck.

Allow-list construction: recursively walk both JSON exports; collect the value of any key whose name (case-insensitively) ends in vndmillionsrounded, formatted with comma grouping (f"{round(value):,}") — this generalizes across the varying key names actually present (vndMillionsRounded, monthlyVndMillionsRounded, bauMonthlyVndMillionsRounded, ...). Also collect every sweep strike value and the passCount. Union with a small, individually-commented EXTRA_ALLOWED set for derived on-slide sums that aren't a raw export field (currently one entry: 2,617 = the M2 slide's systemService + diffClearing fee sum).

A slide figure passes if its extracted token is a member of that allow-list; the checker prints every token's slide index and verdict, then exits 1 if any verdict is a mismatch.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • The checker only catches comma-thousands-grouped figures (≥1000). A tampered sub-1000 number (e.g. the CfD line, 500) would not currently be caught — discovered directly during the tamper test, when the first attempt (tampering CfD by +1) silently passed because "501" has no comma. This is a known, documented limitation of the regex-based approach, not a silent gap: it matches every figure format actually used on these slides today (all VND-millions figures shown are ≥1000 except the CfD line, which nets small in this scenario). If a future slide shows a sub-1000 VND-millions figure, the regex should be widened.
  • Second-best alternative (rejected, per the plan's ALT-004): put the parity check inside the existing quality job. Rejected because it needs Python + regenerated JSON artifacts and would slow the app-only feedback loop; a parallel job keeps both fast and independently red/green.
07 / Errors / Warnings / Flags

Errors / Warnings / Flags Encountered

  • Self-caught bug: the first version of collect_spine_numbers matched keys named exactly vndMillionsRounded, missing spine-s1.json's other field-name variants (monthlyVndMillionsRounded, bauMonthlyVndMillionsRounded). This caused a false PARITY FAIL on the legitimate cold-open figure "11,020" on the very first run. Fixed by matching any key ending in vndmillionsrounded (case-insensitive) instead of an exact key name; re-ran and confirmed PARITY PASS.
  • Self-caught test-design issue: the first tamper-test attempt (CfD 500→501) produced no detectable change because 501 has no comma grouping and the regex never sees it. Recognized this immediately from the unchanged PARITY PASS output, switched the tamper target to a comma-grouped figure (marketEnergy 5,947→5,948), and confirmed the checker correctly failed with the exact offending slide and token named.
  • No test, lint, or build failures. Full battery green after every change in this phase: vitest 51/51, eslint clean, playwright e2e 27/27, production build clean, deck audit PASS, parity PASS.
