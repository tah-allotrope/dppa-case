## Design Decisions

### Why inline `<style>` for loading state
The plan specifies that the splash must be visible "before CSS bundle loads." Putting the loading styles in `app/src/style.css` (which is loaded as a separate stylesheet) means the splash would render unstyled for a few hundred ms. Inlining the styles guarantees the splash looks right from the very first paint.

### Why aria-live="polite" on splash
Screen readers should announce the loading state but not interrupt whatever the user was doing. `aria-live="polite"` queues the announcement until the screen reader is idle.

### Why alt="" on the logo
The logo is decorative context for the loading text; the text "Loading DPPA Calculator…" is the actual announcement. Setting `alt=""` makes screen readers skip the image rather than announce "Allotrope logo" — less noise.

### Why use existing favicon.svg for apple-touch-icon
The plan calls for `apple-touch-icon` and the existing `public/favicon.svg` works at iOS home-screen sizes (180x180 derived from the SVG's viewBox). A separate `apple-touch-icon.png` would be a Sprint 2+ nice-to-have.

## Risk Assessment
- **RISK-02-01** (inline styles flash on fast connections) — mitigated: loading styles match the app's `--bg` and color tokens, so the transition from splash → app shell is nearly invisible.
