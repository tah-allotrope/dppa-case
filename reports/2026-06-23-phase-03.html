Architecture Decision

Stable canvas pattern (matching renderProfileChart)

renderAppShell creates the #multiYearChart canvas once in the static HTML. renderMultiYearPanel updates only text node content (rollup pills, parameter display). renderMultiYearChart checks for an existing Chart.js instance and calls .update('none') instead of destroying and recreating — exactly the same pattern as renderProfileChart in chart.js.

This was critical to avoid: destroying the chart instance on every slider change would cause a visible flash and wasteful DOM teardown. The stable canvas approach means the chart responds to slider input at effectively 0 ms latency.

Multi-year panel position in shell

The multi-year panel is placed after the controls panel — not between .story-grid and .lower-grid. This preserves the .story-grid + .lower-grid CSS adjacent-sibling selector relied on by the existing ui.test.js shell test. Had the panel been inserted between those two sections, the test assertion would have failed.

Workshop tool is now live-interactive for multi-year economics. A participant can drag the EVN escalation slider from 2% to 6%, see the crossover year shift from "never in 20 yr" to "Year 14," all without a page reload. The controls and panel update together in one updateView() call.

Limitations / Second-Best Alternative

No annotation plugin for crossover line. A vertical dashed line at the crossover year would make the chart immediately scannable. Chart.js annotation plugin was not added to keep the bundle clean. The crossover year is visible from the chart shape and the crossover pill — adequate for the workshop.
Alternative UI approach considered: Render the multi-year panel as a separate HTML table with yearly rows rather than a Chart.js visualization. Rejected — a CFO audience reads a line chart faster than a 20-row table for a crossover-year argument.
