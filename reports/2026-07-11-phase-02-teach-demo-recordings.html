03 / Math / Algorithm Used

Math / Algorithm Used

No settlement math changed. The only "algorithm" in this phase is the aspect-fit placement reused from the deck's existing add_picture_fit pattern, applied to the embedded movie so it centers within the same 0.5in/0.9in/9.0in/3.9in slide region every other fallback visual uses:

ratio = min(max_width / image_width, max_height / image_height)
w = image_width × ratio, h = image_height × ratio
x = left + (max_width − w) / 2, y = top + (max_height − h) / 2

where image_width/height come from the poster PNG (so the movie frame is sized identically to how the poster would have been placed as a static picture), and all other symbols are inches on the slide canvas.

06 / Limitations / Second-Best Alternative

Limitations / Second-Best Alternative

  • Headless Chromium's smooth-scroll and Chart.js animation timing may render very slightly differently than a live demo would look to the room. Accepted because ?present=1 is applied during recording (matching the projector theme) and these are fallback slides only played if the live app fails — clarity, not pixel-perfect fidelity to a live session, is the bar.
  • PowerPoint autoplay/click-to-play behavior for embedded MP4s has not been confirmed in real PowerPoint from this session (no PowerPoint available in this environment). This is flagged as a human-only manual check (MANUAL-001 in the plan) and is already on the facilitator's pre-session checklist.
  • Second-best alternative (rejected, per the plan's ALT-001): a human screen-records the six demos manually. Rejected because that is the exact failure mode that left the fallbacks empty since July — not regenerable, blocks on human availability, and drifts silently the next time a scenario number changes.
07 / Errors / Warnings / Flags

Errors / Warnings / Flags Encountered

  • Fixed in this session: the first recording pass produced 5 identical, tiny (4,346-byte) poster PNGs for modules 2-6 — ffmpeg -frames:v 1 was grabbing frame 0 of each clip, captured mid-navigation before the page settled. Fixed by seeking 2 seconds from end-of-file (-sseof -2) before extracting the poster; re-ran the full recording and confirmed all 6 posters now carry real, varied content (464-740 KB range).
  • Environment quirk (not a code bug): the shell's ambient PYTHONPATH points at a broken sandboxed venv (missing native lxml/Pillow extensions), which makes bare py invocations fail. The repo's own documented convention (PYTHONPATH= py script.py) sidesteps this; every Python command in this phase used that prefix and succeeded.
  • Flagged, not resolved: the orchestrator's instructions contained a contradiction — a detailed, explicit "execute the first two phases, then STOP, do NOT execute phase 3" block, followed by a trailing line reading "Execute first three phase with git commit push at end." The explicit stop instruction was treated as authoritative and PHASE-03 was not started.
