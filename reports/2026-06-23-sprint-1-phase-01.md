## Design Decisions

### Why console.error + fallback (not silent swallow)
Every catch block calls `console.error()` so developer tools still surface the real problem. The fallback UI prevents blank panels from being visible to the audience.

### Why showMermaidFallback guards on token
Mermaid has a render-token guard pattern (line 11 `mermaidRenderToken`) to prevent stale renders from overwriting fresh ones. The fallback must respect the same guard, otherwise a fast error-and-rerender sequence could leak a fallback message into a later successful render. The implementation checks `if (token === mermaidRenderToken)` before injecting the fallback.

### Why wrap renderMultiYearChart too
The phase-04 workshop-tool plan added a multi-year cumulative chart. It's another chart that could fail (e.g., canvas init error), so it gets the same treatment as `renderProfileChart`.

## Risk Assessment
