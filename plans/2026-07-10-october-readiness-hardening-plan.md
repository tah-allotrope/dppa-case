## Specification

Gate-sweep math (PHASE-03). All prices in **VND/kWh**, all volumes in **kWh/month**,
all bills in **VND/month**.

**Grid (56 cells = 8 × 7):**
- Strike axis: `strike ∈ {1100, 1150, 1200, 1250, 1300, 1350, 1400, 1450}` VND/kWh
  (8 values, brackets the S1 strike of 1,250).
- Volume axis: `ratio ∈ {0.70, 0.80, 0.90, 1.00, 1.10, 1.20, 1.30}` (7 values,
  contracted volume as a fraction of the S1 contracted quantity).

**Fixed inputs (year 1), sourced from `app/src/data/default-scenarios.js` — read them
from the module, do not re-type:**
- `load = 5,000,000` kWh/month (S1 `monthlyVolumes.total`)
- `contracted(ratio) = round(5,000,000 × ratio)` kWh/month
- `fmp₁ = 1,150` VND/kWh (workshop1 `overrides.marketPrice`)
- `retail₁ = defaultInputs.retailTariff` (2,204 VND/kWh)
- `serviceFee = defaultInputs.dppaServiceFee`, `clearingFee = defaultInputs.dppaClearingFee`
- `lossFactorPrecise = 1.026 × 1.008`, `lossFactorKppOnly = 1.008`
  (same constants as `app/scripts/export-spine.mjs`)

**Yearly escalation (n = 1…20):** `g = 0.04` for retail, strike, and FMP (ASM-005):
`retailₙ = retail₁ × 1.04^(n−1)`, `strikeₙ = strike × 1.04^(n−1)`,
`fmpₙ = fmp₁ × 1.04^(n−1)`.

**Per-cell, per-year bill:** call the existing
`buildFiveLineBill({fmp: fmpₙ, strikePrice: strikeₙ, serviceFee, clearingFee,
lossFactorPrecise, retailTariff: retailₙ, lossFactorKppOnly},
{contracted: contracted(ratio), total: load})` — where `buildFiveLineBill` already
computes: marketEnergy = contracted × fmp × lossFactorPrecise; fees = contracted ×
(serviceFee + clearingFee); additionalPurchase = max(load − contracted, 0) × retail;
cfd = contracted × (strike − fmp); `cKh` = sum of all five lines (the factory's total
monthly DPPA-world bill).

**Gates per cell:**
1. **Buyer gate:** `Σₙ₌₁²⁰ (12 × cKhₙ) ≤ Σₙ₌₁²⁰ (12 × load × retailₙ)` —
   lifetime with-DPPA cost no worse than lifetime business-as-usual cost.
2. **Lender gate (proxy, ASM-003):** `strike ≥ 1.20 × 1,150 = 1,380` VND/kWh —
   the developer's locked realized price (market + CfD = strike per contracted kWh)
   covers illustrative per-kWh debt service at a 1.20× DSCR.
3. **Investor gate (proxy, ASM-003):** `strike ≥ 1,450` VND/kWh — locked realized
   price at or above illustrative full LCOE (debt service + equity return).
- `allPass = buyer AND lender AND investor`; `passCount = count(allPass)` over 56 cells.

**Data-driven label rule (ASM-004):** every artifact renders
`f"{passCount} / 56"` from `assets/teaching/gate-sweep.json`; the string `0 / 56` must
not appear as a literal anywhere in `build_teaching_visuals.py` or
`build_oct_teaching_deck.py` after PHASE-03.

## Gotchas

- **`PYTHONPATH=` prefix:** the repo's documented Python invocations clear
  `PYTHONPATH` (`PYTHONPATH= py script.py`). In PowerShell use
  `$env:PYTHONPATH=''; py script.py`. Omitting it can pick up stray module paths.
- **VND units trap:** `spine-s1.json` carries BOTH exact VND (`vnd`) and rounded
  millions (`vndMillionsRounded`). Slides use millions ("tr VND"); the sweep and
  parity whitelist must not mix the two scales — a 1e6 mix-up will "pass" visually
  and fail parity.
- **`buildFiveLineBill` volume semantics:** `shortfall = max(total − contracted, 0)`;
  when `contracted > total` (sweep ratios > 1.0) there is no shortfall line but
  marketEnergy/fees/CfD still scale with `contracted` — that IS the over-contracting
  lesson; don't "fix" it.
- **Word-budget asserts are load-bearing:** `build_oct_teaching_deck.py` hard-asserts
  ≤30 words inside `content_slide()`/`cold_open()`. When interpolating the data-driven
  pass-count (PHASE-03), a two-digit count keeps the same word count as "zero"; just
  don't add words.
- **`reuseExistingServer: false`** in `app/playwright.config.js` means port 4173 must
  be free; the recording script uses port **4174** to avoid colliding with a
  concurrently running e2e suite.
- **npm install, not npm ci** in CI — a deliberate workaround for
  optional-native-dependency lockfile drift (comment in `ci.yml`). Do not "fix" it
  back to `npm ci` in the new job.
- **Deck asserts run at import-build time:** if `gate-sweep.json` or a fallback MP4 is
  missing, the deck build should degrade (placeholder/GIF path), not crash — preserve
  the existing existence-check style (`os.path.exists`) when extending
  `fallback_slide()`.
- **`prs.slides._sldIdLst` access in `build_oct_teaching_deck.py:303`** is private-API
  spelunking that works on the pinned `python-pptx`; leave it alone.
- **Speaker notes are exempt** from the ≤30-word budget and from the parity checker's
  slide-body scan (they intentionally contain exact answer-key numbers); the checker
  must skip `notes_slide` text or it will false-fail.
- **Git Bash vs PowerShell:** all commands in this plan are Git Bash syntax; on
  PowerShell 5.1 `&&` is unavailable — run commands separately.

  the session if engine constants move. Mitigation: the CI drift step (PHASE-04) fails
  the build the moment committed JSON and engine disagree, forcing a conscious
  re-render + narrative review rather than a silent stale slide.
- **RISK-002:** ffmpeg-static adds a ~80 MB platform binary to `app/node_modules` —
  dev-only, never bundled; acceptable versus requiring a system ffmpeg install.
- **ALT-001:** Record demos with a human screen-capture tool — rejected: not
  regenerable when numbers/UI change, and blocks on human availability (the exact
  failure mode that left the fallbacks empty since July).
- **ALT-002:** Model true developer-side DSCR/IRR (debt schedule, capex, P50 yield)
  for the lender/investor gates — rejected for this plan: `settlement.js` is
  buyer-side by design (CON-001); illustrative per-kWh proxies stored in JSON meta are
  honest, recalibratable, and sufficient for the teaching point.
- **ALT-003:** Move root build scripts into `tools/` during cleanup — rejected
  (ASM-008): path churn before October risks breaking documented commands for zero
  session value; revisit post-October.
- **ALT-004:** Put the parity checker inside the existing `quality` CI job — rejected:
  it needs Python + regenerated JSON artifacts and would slow the app feedback loop;
  a parallel job keeps both fast and independently red/green.
