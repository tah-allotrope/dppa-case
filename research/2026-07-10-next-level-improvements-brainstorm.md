# Brainstorm: DPPA-Case — Next-Level Improvements (Post-Revamp, Pre-October 2026)

## Where the project stands today (grounded snapshot, 2026-07-10)

The mission (MISSION.md) is to teach the Vietnam DPPA pricing session; after July 2026's
symbol-overload failure, the **October 2026 Modules 1–6 teaching revamp** was planned
(`research/2026-07-04_…brainstorm.md`, `plans/2026-07-04-…plan.md`) and **largely implemented**
(commit `9773440`, report `reports/2026-07-04-modules-teaching-revamp-implementation.md`):

- **EN deck rebuilt** — `ceba/DPPA Presentation Oct 2026 To Teach.pptx` (27 slides) generated by
  `build_oct_teaching_deck.py` from the 44-slide master; `audit_teaching_deck.py` passes
  (≤30 words/slide, 0 pre-decoder Decree-57 symbols); full speaker notes.
- **App teach mode** — `?teach=1` six-step presenter flow (`app/src/modules/teach.js`), plus
  `?present=1` projector theme, first-visit bilingual tour, token-driven dual-theme visual
  system, Playwright e2e + visual snapshots, ESLint/Prettier, GitHub Actions CI
  (commits `ed21985`→`26b1684`, plan `plans/2026-07-05-app-quality-visuals-testing-plan.md`).
- **Numbers pack** — `app/scripts/export-spine.mjs` → `assets/teaching/spine-s1.json`; every
  deck/card/worksheet figure traces to `settlement.js` (the canonical engine, 476 ln, tested).
- **Print artifacts** — `lessons/0012-reference-card/` (A4 card + M5 worksheet); facilitator
  guide has the 60-min run-of-show.
- **Trilingual visual pipeline** — `build_teaching_visuals.py --lang en|vi|zh` renders all
  seven visual families localized.

**The remaining critical path to October is no longer "build the thing" — it is closing the
declared gaps, de-risking the live session, and hardening the artifact pipeline.** The ideas
below are ranked accordingly.

## Theme A — Close the declared implementation gaps (highest value, all automatable)

### A1. Automate the six teach-mode fallback recordings with Playwright video ⭐
The implementation report marks TASK-02-05 ("record six GIF/MP4 demos") as *needs a human* —
but it doesn't. Playwright (already a dev dependency, already driving teach mode in
`app/e2e/teach.spec.js`) can record video natively:
- New script `app/e2e/record-teach-demos.spec.js` (or a standalone `scripts/record-demos.mjs`):
  launch `vite preview` at 1280×720, step through each of the six teach steps with realistic
  pauses and slider drags, `recordVideo` → six `.webm` files.
- Convert to MP4/GIF with ffmpeg (or keep MP4; PowerPoint embeds MP4 fine per ASM-003).
- Drop into `assets/teaching/fallback/`, and extend `build_oct_teaching_deck.py` to embed them
  on the hidden fallback slides (it already has the slide slots — they currently show
  placeholder text).
This converts the single biggest "human required" contingency item into a reproducible build
step. When numbers or UI change, re-run one command and the fallbacks are current again.

### A2. Wire the M5 heatmap to a real 56-scenario sweep
The gate-sweep heatmap is flagged **illustrative** — it carries the "0 of 56" punchline without
computed backing. Fix inside the existing pattern:
- Extend `app/scripts/export-spine.mjs` (or a sibling `export-sweep.mjs`) to run
  `projectMultiYear`/`buildFiveLineBill` across the strike × horizon grid (the deck narrative
  implies ~20 strikes × cases) and emit `assets/teaching/gate-sweep.json` with per-cell
  buyer/lender/investor gate pass/fail.
- Re-render the heatmap in `build_teaching_visuals.py` from that JSON.
If a CFO in the room asks "what strike *would* pass all three gates?", the answer is then
computed, not asserted — exactly the credibility the session needs.

### A3. Execute PHASE-06 translation prep now (without violating the freeze gate)
DEC-018 correctly gates vi/zh-cn deck cloning on content freeze, but the *terminology map*
(TASK-06-01) can and should be built now:
- Extract the established VI/ZH vocabulary from `lessons/0009–0011-{vi,zh-cn}.html`, the
  worksheets docx, and `reference/dppa-glossary.html` into a reviewable
  `research/dppa-terminology-map.{md,json}` (EN term → VI → ZH, with source file citations).
- Restructure `build_oct_teaching_deck.py`'s `TEXT` dict so line 81's placeholder
  (`TEXT["vi"] = TEXT["en"]`) becomes a load from that map with explicit
  `UNTRANSLATED` markers — then post-freeze cloning is a fill-in-the-blanks pass, not a
  translation project under deadline.

### A4. QR code on the close slide (trivial)
`pip install qrcode[pil]` (or a dependency-free QR generator) → render QR for
https://dppa-case.web.app into `assets/teaching/`, embed in the close slide via the deck build
script. Currently a plain-text URL; flagged in the report.

## Theme B — Repo integrity & reproducibility (quiet risks, cheap fixes)

### B1. Two build-critical files are UNTRACKED in git ⚠️
- `lessons/DPPA_Scenario_Answer_Summary.docx` — the **template** that
  `build_worksheet_answer_docx.py:32` copies to produce the worshop handout. If this machine
  dies, the handout build breaks silently.
- `ceba/DPPA Presentation July 2026 To Teach.pptx` — the July deck, explicitly designated the
  A/B reference of "what confused the room" (DEC-020/ALT-001).
Both should be committed. This is the single cheapest risk-elimination in the repo.

### B2. Untrack `app/.firebase/hosting.ZGlzaA.cache`
`.gitignore` now covers `.firebase/`, but the cache file was tracked before the rule landed, so
it shows as perpetually modified (`git rm --cached`). Pure noise removal.

### B3. Root directory archaeology cleanup
147 tracked PNGs, most of them April-era manual QA screenshots at the repo root
(`mobile-scroll-*.png`, `desktop-*.png`, …), plus stale JSON probe files, `nul`, duplicate
py/js one-off scripts (`apply_corrections.py` vs `apply_deck_corrections.{py,js}`,
`verify_deck_app_parity.{py,js}`), and a root `node_modules` for the legacy `build-deck.js`.
Proposal: `git rm` the obsolete screenshot/probe debris (the Playwright visual-snapshot suite
now owns visual QA), move living build scripts into `tools/`, and note in README which
generator owns which artifact. Keeps `git status`/`ls` honest and makes the repo navigable for
the fresh-viewer colleague or any collaborator.
*Assumption adopted (unattended run): screenshots superseded by the Playwright visual suite are
safe to delete from HEAD — they remain recoverable in git history.*

### B4. Deck ↔ engine parity check in CI
`audit_teaching_deck.py` checks word budget and symbols, but nothing re-verifies that the
**numbers on the slides still match `settlement.js`** after an engine or scenario change. Add a
`verify_deck_numbers.py` step: extract text from the Oct pptx, find every VND figure, reconcile
against `spine-s1.json`; run it (plus the audit) in `.github/workflows/ci.yml`. This
mechanizes ASM-001 ("no slide figure hand-typed without reconciling") permanently — today it
was verified once, by a one-off script mentioned in the report but not kept.

## Theme C — De-risk the October session itself

### C1. Fresh-viewer test kit (makes PHASE-05 schedulable)
The one validation that proves DEC-003 needs a human volunteer. Lower the activation energy:
a self-contained packet (`facilitator/fresh-viewer-kit/`) with instructions for the volunteer,
the M5 worksheet, a pass/fail rubric keyed to the success criterion, and a short structured
feedback form. The user then only needs to find the person, not design the test.

### C2. Presenter cue card + timer discipline
Derive a printable one-page run-of-show cue card (module → minutes → app step → checkpoint
question) from the facilitator guide, and optionally add a small elapsed-time indicator to
teach mode (`?teach=1` already knows which of six steps is active; showing "step 3/6 · target
08:00–16:00" keeps the 60-min budget honest on stage).

### C3. Offline resilience: PWA/service-worker for participants' phones
CON-003 covers the *presenter* (local vite preview), but participants self-serving on iPhones
depend on venue wifi. A minimal service worker + manifest (the app is a static bundle,
~255 kB) makes it install-once/work-offline. Also gives an app icon when saved to home screen.
Scope: cache-first for the built assets, nothing dynamic — a day's work with the existing
Playwright suite to guard regressions.

### C4. Backwards-planned October timeline
Q-001 (exact session date) is still open. Adopt the brainstorm's recommended default and make
it concrete: a dated checklist (early Sep: recordings+heatmap+deploy done; mid Sep: dry-run +
fresh-viewer; freeze; late Sep: vi/zh clones + print). Could live in `activeContext.md` or a
`plans/2026-october-readiness-checklist.md` with checkboxes.

## Theme D — App evolution (post-October or if time allows)

### D1. Full app i18n (VI/ZH language toggle)
Deliberately deferred twice (ALT-005 in both brainstorms) — but it is the largest remaining
mismatch: lessons, worksheets, decks, and visuals are trilingual; the app participants touch is
English-only (tour strings excepted). The token/tour groundwork and the small UI surface
(~dozens of labels + chart legends) make this tractable now: a `?lang=vi|zh` param + strings
module reusing the terminology map from A3. Directly serves the actual audience (Vietnamese/
Chinese factory CFOs).

### D2. FMP reality upgrade: CSV import or a real proxy series
RESOURCES.md flags FMP ~1,427 as illustrative and "primary FMP data not publicly published" as
a gap. Two complementary moves:
- **App feature:** an "import FMP series (CSV)" affordance (or a pasted-JSON dev door) so that
  when Allotrope obtains a real/proxy series (NSMO/ERAV, or a client's settlement statement),
  the same app demos with real market shape — powerful for lender conversations.
- **Research task:** hunt a public proxy (Vietnam CGM SMP publications, academic/market
  reports) and record findings + official Decree 57/Circular 16 source URLs in RESOURCES.md.

### D3. Sensitivity/negotiation view ("five levers" live)
M6 teaches five negotiation levers; the app currently proves M2–M5. A compact tornado/sensitivity
panel — bill delta per lever (strike ±50, FMP ±100, k/K_pp, fees, contract quantity) computed
straight from `settlement.js` — would give M6 its own scripted app moment (today M6's demo is
the weakest of the six) and doubles as a real advisory tool.

### D4. Shareable state via URL params
Scenario + slider positions encoded in the query string (`?s=workshop2&strike=1500…`) so the
presenter can bookmark exact demo states, the deck's QR codes can deep-link each module's app
moment, and participants can share configurations. Small change in `main.js` state handling;
teach-steps could then be defined *as* URLs, simplifying `teach-steps.js`.
